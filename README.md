# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- **演出模板 / 场次调整分开保存**：模板拥有固定流程（提示顺序、时长、负责人及灯光、音响、道具、演员等基础值）；场次只保存本场覆盖、本场顺序、本场停用项与本场自有提示，两边各自独立状态所有权。
- 有效提示表由纯函数合并（模板版本 + 覆盖 + 本场提示）；模板工作版一改，所有跟随最新版且未覆盖的场次立即按新值重算。
- 模板可发布不可变版本；锁定场次即钉版，模板继续升级也不影响本场，需要时再迁移。迁移按 cueId 保留覆盖，失配覆盖转入「待处理覆盖」不丢数据，可人工恢复或删除。
- 复制新场次时选择模板：先校验模板（空标题、时长非法、负责人空缺等），再在深拷贝工作区内提交；任一步失败整体回滚，原场次与模板都不少数据，并持久化待处理任务，刷新重开后可继续重试或放弃。
- 旧版（场次内嵌提示）数据与旧锁定快照在加载时自动迁移：一场一模板、空覆盖，提示仍可完整解析。
- 提示点原生拖拽排序；场次拖动只记录本场顺序覆盖，模板顺序不变，时间轴自动顺延。
- 检查负责人空缺、同场时间冲突、跨场道具撞场、演员撞场、失效引用，以及模板缺失、钉版版本丢失、可迁移等归属问题。
- 复制上一场（模板引用与本场覆盖各自深拷贝独立）；锁定完整工作区版本，按提示逐条比较合并视图差异。
- 文档级撤销/重做（成功的模板套用同样可撤销）、键盘顺序调整、搜索和浏览器本地持久化。
- 可交互的首演示例数据覆盖两个模板、两个场次、本场覆盖与待处理问题。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Alt + ↑ / ↓` | 将当前提示前移或后移 |
| `N` | 新建提示（表单编辑区域外） |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
