# 舞台演出串联与提示表编辑器

导演和舞台监督使用的纯前端提示表工作台。可按幕、场和提示点维护演出流程，拖动后自动顺延后续时间，并持续检查负责人、时间、道具、演员和引用关系。

## 功能

- **模板 / 场次状态分离，各自独立所有权**：模板拥有提示的顺序、时长、负责人与灯光音响道具演员等默认值，按 append-only 版本演进；每个剧场场次只保存本场的稀疏覆盖（`cueOverrides`），复制新场次从模板干净继承，不会把上一站的临时调整带过去。
- **模板一改即时重算**：未覆盖字段始终解析模板当前版本；场次保留 `templateVersion` 标记，需要时一键迁移到新版本，按稳定提示 key 匹配覆盖，模板已删除提示的覆盖作为「孤立项」保留，不丢数据。
- 旧的整份深拷贝数据（schema v1）与历史锁定快照在首次打开时自动无损迁移到模板 + 场次模型。
- 模板库中按幕、场维护提示顺序（原生拖拽）、时长、负责人与灯光、音响、道具、演员、备注，发布后形成不可变新版本。
- 复制新场次时选择模板，套用走事务：预检通过后单次原子提交；失败先回滚，原场次与模板均不改动，作业单独持久化，重开页面可「继续处理」或移除。
- 在生效视图上检查负责人空缺、同场与跨场道具/演员撞场、失效前置引用、模板缺失、孤立覆盖与待迁移版本。
- 锁定场次或保存锁定版本，选择锁定版本后逐条比较负责人、时长和流程差异。
- 文档级撤销/重做、搜索和浏览器本地持久化。
- 可交互的巡演示例：一个通用模板 + 两个剧场场次，各自仅持有少量本场覆盖。

## 架构（纯函数内核）

- `app/models/cue-book.ts`：领域类型（模板版本、场次稀疏覆盖、套用作业）。
- `app/lib/cue-book/`：与 UI 无关的纯函数——`resolve`（模板+覆盖合并）、`template`（草稿/发布/覆盖迁移）、`apply`（事务预检/回滚/续处理）、`migration`（v1→v2 与作业恢复）、`validation`、`override`（生效值→稀疏覆盖）、`repository`（localStorage 与旧键迁移）。
- `app/components/cue-editor.*`：仅负责交互与持久化编排。

## 技术栈

- Ember 5
- TypeScript
- Ember Paper
- Glimmer 组件
- 原生 `localStorage`

## 本地开发

```bash
npm install
npm start
```

浏览器打开终端输出的开发地址。

## 生产构建

```bash
npm run build
```

生产文件位于 `dist/`。

## 键盘操作

| 快捷键 | 操作 |
| --- | --- |
| `Ctrl/Cmd + Z` | 撤销 |
| `Ctrl/Cmd + Shift + Z` 或 `Ctrl/Cmd + Y` | 重做 |

> 提示顺序只归模板所有：在「模板库」模式内拖拽调整，场次侧不单独排序。

## Docker

容器内由 nginx 监听端口 `80`，源码不硬编码宿主端口。

```bash
docker build -t stage-cue-prompt-editor .
docker run --rm -p 10013:80 stage-cue-prompt-editor
```

宿主端口 `10013` 仅作为本地运行示例，实际端口由根编排文件统一管理。
